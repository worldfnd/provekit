ProveKit connects circuit authoring, constraint generation, key preparation, proving, verification, and optional recursive-verifier export. The CLI wraps this lifecycle in three primary commands: `prepare`, `prove`, and `verify`.

## Mental model

<CardGrid>
  <Card title="Author in Noir">
    Write the computation and public/private input boundary in a Noir package.
  </Card>
  <Card title="Prepare once per circuit version">
    Compile the circuit and produce a matching `.pkp` prover key and `.pkv` verifier key.
  </Card>
  <Card title="Prove per witness">
    Bind the prover key with concrete witness inputs from `Prover.toml` or an SDK witness map.
  </Card>
  <Card title="Verify wherever needed">
    Verify the proof with the matching `.pkv` locally, in a service, in WASM, through FFI, or through recursive-verifier tooling.
  </Card>
</CardGrid>

## Core concepts

| Concept | Description |
| :--- | :--- |
| Noir | User-facing circuit language used for ProveKit's primary authoring path. |
| ACIR | Intermediate representation emitted by the Noir frontend. |
| R1CS | Constraint system used by the ProveKit proving pipeline. |
| Prover key (`.pkp`) | Key material used to generate a proof for a prepared circuit. |
| Verifier key (`.pkv`) | Key material used to verify proofs generated for the matching prepared circuit. |
| WHIR proof | Proof object generated by the ProveKit prover and consumed by verification paths. |
| Recursive-verifier export | `params_for_recursive_verifier` and `r1cs.json` derived from a matching verifier key and proof. |

## Command responsibilities

| Command | Responsibility | Typical cadence |
| :--- | :--- | :--- |
| `prepare` | Compile the program and write `.pkp` / `.pkv`. | When circuit source, compiler backend, hash choice, branch, or proof format changes. |
| `prove` | Generate `proof.np` from a prover key and inputs. | Once per witness or proof request. |
| `verify` | Verify a proof against a verifier key. | At every trust boundary. |
| `show-inputs` | Decode public inputs from a verifier key and proof. | During integration and production validation. |
| `generate-gnark-inputs` | Export recursive-verifier inputs from a verifier key and proof. | Whenever the verifier key or proof changes. |

## Trust and setup boundary

<Aside type="caution" title="Do not infer compatibility from filenames">
Files named `basic.pkp`, `basic.pkv`, and `proof.np` are compatible only when they were generated from the same circuit configuration and branch/commit. Use provenance records and checksums for deployment artifacts.
</Aside>
