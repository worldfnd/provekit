ProveKit ships one proof pipeline and several runtimes that drive it. Pick by where verification needs to live and what host language you're shipping in.

## Proving across hosts

The v1.0.2 `.pkp` is generated once per circuit. These are the tested ways to use it:

<Tabs>
<TabItem label="CLI">
```sh
provekit-cli prove --prover app.pkp --input Prover.toml --out proof.np
```
</TabItem>
<TabItem label="Rust">
```rust
use provekit_common::{file::read, Prover};
use provekit_prover::Prove;

let prover: Prover = read("app.pkp")?;
let proof = prover.prove_with_toml("Prover.toml")?;
```
</TabItem>
</Tabs>

Verification usually lives in a backend, a contract gateway, or an HTTP service. See the [Rust guide](/e2e/rust/) for the tested verify-side call.

## Verifier server

[`tooling/verifier-server`](https://github.com/worldfnd/provekit/tree/v1.0.2/tooling/verifier-server) exposes an Axum HTTP service:

| Route | Method | Purpose |
| :--- | :--- | :--- |
| `/health` | `GET` | Server health, version, and timestamp. |
| `/verify` | `POST` | Verify a JSON proof using downloaded artifacts. |

A verification request looks like:

```json
{
  "pkvUrl": "https://example.com/verifier.pkv",
  "r1csUrl": "https://example.com/r1cs.json",
  "pkUrl": "https://example.com/proving_key.bin",
  "vkUrl": "https://example.com/verification_key.bin",
  "np": { "proof": "NoirProof JSON fields" },
  "verificationParams": { "maxVerificationTime": 300 },
  "metadata": { "requestId": "request-123" }
}
```

`pkUrl`, `vkUrl`, `verificationParams`, and `metadata` are optional. Artifact URLs must use HTTP or HTTPS. The server defaults to one concurrent verification (`VERIFIER_SEMAPHORE_LIMIT=1`) and a 10 MB request body limit; tune both through the `VERIFIER_*` environment variables documented in [`tooling/verifier-server/README.md`](https://github.com/worldfnd/provekit/tree/v1.0.2/tooling/verifier-server).

## Recursive verifier / gnark

Use `generate-gnark-inputs` to bridge a ProveKit prover key and proof into the Go/gnark recursive verifier:

```sh
provekit-cli generate-gnark-inputs \
  artifacts/app.pkp \
  artifacts/proof.np \
  --params artifacts/params_for_recursive_verifier \
  --r1cs   artifacts/r1cs.json
```

Then run the Go CLI or server from [`recursive-verifier/`](https://github.com/worldfnd/provekit/tree/v1.0.2/recursive-verifier) with those files. If you omit the recursive proving and verifying keys, the Go tool can generate them for development; production deployments should manage trusted-setup keys explicitly.
