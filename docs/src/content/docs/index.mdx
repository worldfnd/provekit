ProveKit turns a Noir circuit into a verifiable WHIR proof. These v1.0.2 guides show the tested CLI and Rust flows, plus the compatibility status of other integration paths.
</p>

## See it in three commands

From a checkout of the [v1.0.2 release](https://github.com/worldfnd/provekit/releases/tag/v1.0.2):

```sh
cd noir-examples/basic
cargo run --release --bin provekit-cli -- prepare   # compile circuit → .pkp + .pkv
cargo run --release --bin provekit-cli -- prove     # .pkp + Prover.toml → proof.np
cargo run --release --bin provekit-cli -- verify    # .pkv + proof.np → exit 0
```

That's the CLI proving pipeline. The Rust integration was also verified with v1.0.2 artifacts; check each platform guide before using those artifacts in another runtime. [Walk through it step by step →](/getting-started/quickstart/)

## Core artifacts at a glance

<div class="pk-metric-grid">
  <div class="pk-metric"><strong>.pkp</strong><span>Prover key, produced by `prepare`, consumed by `prove` and recursive export.</span></div>
  <div class="pk-metric"><strong>.pkv</strong><span>Verifier key, produced by `prepare`, consumed by `verify`.</span></div>
  <div class="pk-metric"><strong>proof.np</strong><span>WHIR proof, produced by `prove`, consumed by every verification path.</span></div>
  <div class="pk-metric"><strong>r1cs.json</strong><span>Recursive-verifier R1CS, exported from a matching `.pkp` and proof.</span></div>
</div>

Every artifact is bound to a specific circuit and release. Treat them as versioned deployment objects. See [Artifact lifecycle](/concepts/artifact-lifecycle/) for the full pairing rules.

<Aside type="tip" title="Stable release: v1.0.2">
These guides use the [v1.0.2 release](https://github.com/worldfnd/provekit/releases/tag/v1.0.2), which pins Noir `v1.0.0-beta.26`. `main` is the rolling-development line and may change proof formats, key formats, recursive-verifier inputs, or integration APIs between commits. See [Project status](/reference/project-status/).
</Aside>
